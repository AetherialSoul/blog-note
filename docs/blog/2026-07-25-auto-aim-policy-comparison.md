# 两套自瞄策略的实战切换

今天没有继续堆新功能，而是把两套已经能运行的自瞄策略放进同一个仿真场景对比：原有的 `baseline`，以及参考上科大开源自瞄思路做的 `shtech` 实验策略。

这里的重点不是给某套算法贴上“更强”的标签，而是把它放到可复现的条件下，看看它在什么情况下有用、什么时候和原方案其实走的是同一条路径。

## 两套策略怎么分工

`baseline` 是原项目已有的流程：目标检测后进入旋转目标 EKF，接着由 Aimer 计算提前量，Shooter 在误差满足条件时开火。

`shtech` 是我新加的双策略切换层。它会估计目标的角速度：

```text
低转速：装甲板位置与速度预测 -> Trajectory 解算 -> 开火
过渡区：低速装甲分支与旋转目标分支的云台角度混合
高转速：旋转目标 EKF + MPC Planner
```

阈值目前是：低于 `1.57 rad/s` 用装甲分支，高于 `2.1 rad/s` 用高速旋转分支，中间做平滑过渡。这样做的原因很直接：静止或缓慢运动的装甲板，没有必要套完整的旋转体模型；前哨站高速转动时，只看一块装甲板又会失去稳定性，需要保留原有的旋转目标状态估计。

这不是对 SHtech 整个自瞄系统的逐行移植。当前版本借鉴的是“根据目标运动状态选择合适跟踪模型”的做法，完整的 IESEKF 实现并没有直接搬进来。

## 同条件实战结果

每一局都会重启游戏，目标从 `1500 HP` 开始；哨兵站位、视觉模型、交战窗口均相同，只有 `--aim-policy` 参数不同。结束时还会检查 `release_restored=true`，确认外部程序没有把云台控制权留在游戏里。

| 场景 | 策略 | 子弹 | 有效命中 | 命中率 | 伤害 | 检测率 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 冻结前哨，低转速 | `baseline` | 46 | 42 | 91.3% | 840 | 90.8% |
| 冻结前哨，低转速 | `shtech` | 46 | 42 | 91.3% | 840 | 89.7% |
| 原生旋转前哨，约 `2.5 rad/s` | `baseline` | 45 | 14 | 31.1% | 280 | 65.1% |
| 原生旋转前哨，约 `2.5 rad/s` | `shtech` | 46 | 14 | 30.4% | 280 | 82.3% |

低转速下，两者的伤害和命中率完全相同。高速旋转时，`shtech` 的检测率更高，但有效命中仍然是 14 次。原因不是切换失效，恰好相反：高速区间里 `shtech` 会主动回到旋转目标 EKF 与 MPC 路径，所以两套策略在这一段的核心瞄准逻辑相同。

这轮结果说明两件事：低速装甲分支可以稳定开火；当前实现还没有带来高速旋转目标的命中提升。后者是下一步需要继续验证和调参的地方，不能因为检测率更高就把它说成性能提升。

## 我怎么验证切换真的发生

为了让“切换”不是代码里的一个 `if`，我加了一个冻结前哨的基准场景：

```yaml
bench_freeze_outpost: true
```

它会让红方前哨停止旋转，角速度接近 `0 rad/s`。此时 `shtech` 必须选择低速装甲分支。原生前哨保持约 `2.5 rad/s` 转速时，则进入高速旋转分支。两个场景都能造成伤害，并且结束后控制权能交还，才算这套策略具备继续迭代的基础。

运行时可以这样选择：

```powershell
# 原有策略
.\build\gestalt.exe <ws_port> configs\gestalt_sentry_outpost_static.yaml `
  --setup=1 --fire=1 --timeout=20 --showui=0 --aim-policy=baseline

# 双策略实验版本
.\build\gestalt.exe <ws_port> configs\gestalt_sentry_outpost_static.yaml `
  --setup=1 --fire=1 --timeout=20 --showui=0 --aim-policy=shtech
```

`<ws_port>` 每次启动游戏都会变化，应从游戏日志中查找 `WebSocket server started`，不能复用上次的端口。

## 从 C++ 语法开始，怎么学这部分

如果只学过 C++ 语法，我建议不要从 EKF 公式或 MPC 推导硬读起。先把一次实际开火拆成四个问题，读代码时每次只回答一个。

1. **目标在哪里？** 从 YOLO 检测框开始，理解它只告诉我们图像中的位置；再看 PnP 如何用装甲板尺寸和相机参数还原三维坐标。
2. **目标下一刻在哪里？** 看 `Tracker` 和 `ShtechArmorTracker` 的输入、状态和输出。前者适合旋转体，后者只平滑位置、速度和偏航变化。
3. **云台该转多少？** 读 `Trajectory` 与 Aimer。它们把未来目标位置变成 yaw、pitch，并把子弹飞行时间算进去。
4. **什么时候允许开火？** 看 `Shooter` 和 `command.shoot`。开火不是检测到目标就扣扳机，而是要等云台角度足够接近解算结果。

比较代码时，也先盯住一条很短的调用链：

```text
src/gestalt.cpp
  -> 选择 baseline / shtech
  -> Tracker 或 ShtechArmorTracker
  -> Trajectory / Planner
  -> command.shoot
  -> GameLink 发送到游戏
```

把程序以 `--fire=0` 跑一遍，只观察日志里的角速度、策略选择和云台角度；理解后再开启 `--fire=1`，对照 HP、子弹数和有效命中。这样学到的每个类和函数都能回到游戏画面里验证，不会只停留在语法层面。
