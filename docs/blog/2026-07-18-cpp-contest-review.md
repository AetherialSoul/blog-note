# 2026-07-18：用竞赛题复习 C++ 基础

今天没有继续开新课，而是回头做了前面学过的 C++ 竞赛题。题目来自整理进资料包的 XMUOJ 361 题组，按课程分到了基础语法、控制流、函数、数组和字符串这些已经学过的部分。

这次复习的感觉和做课堂 `practice` 不一样。课堂练习把一个知识点拆得很干净，竞赛题会把输入、边界、输出格式和已有知识揉在一起。写完以后才知道，自己是不是真的能从题目开始组织程序。

## 先按课程找题，而不是随便挑题

题库现在已经按课程标了题号。例如基础输入输出归到第 01 课，分支和循环归到第 02 课，引用参数和数组传参归到第 03–05 课。

这样做有一个直接好处：题目不会跳级。碰到一题时，先知道它是为了复习什么，再决定要不要做，而不是看到“算法题”三个字就把哈希、图论和动态规划一起翻出来。

今天主要复习的是这些能力：

- 读清输入，确认有几个数、每个数代表什么。
- 用函数拆开计算和输出，而不是把所有东西堆在 `main`。
- 用数组或 `vector` 保存一组数据，再按题目要求遍历。
- 在提交前检查行末空格、换行和边界输入。

## 题面和样例不一致时，先停下来

复习 361.86 和 361.89 时，遇到了输入描述、样例和本地整理题解对不上的情况。

比如 361.86 的本地参考代码假设先读 `n m size`，再读两个数组；但原题样例的格式并不能由这份整理资料可靠地解释。361.89 也出现了矩阵尺寸与后续展示行数对不齐的问题。

这类情况不能靠“猜一个格式然后硬写”。我把规则改成了：

1. 以 OJ 原题页面的输入描述和样例为准。
2. 如果题面和样例仍冲突，先做一个最小输入测试，不把本地题解当成唯一标准。
3. 整理资料中的参考代码只用于核对思路，不能替代读题。

这不是小题大做。输入格式一旦理解错，后面的算法写得再对也不会通过。

## 今天留下的复习方式

后续每一课都会沿用同一个顺序：先通过课堂 `practice`，再做课程里标出的必做竞赛题；独立思考一段时间后，再查看题解的思路和实现。每道题至少留下数据范围、边界、复杂度和错因。

题目不需要一天刷很多。能写清“为什么这里要用引用”“为什么这个数组能原地修改”“为什么这个输入要按行读”，比只记住一道题的代码更有用。
