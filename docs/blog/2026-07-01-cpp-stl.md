## 今天复习的重点

### STL 容器

今天重新过了一遍常见容器的特点：

| 容器 | 适合场景 | 需要注意的点 |
| --- | --- | --- |
| `vector` | 顺序存储、随机访问、动态数组 | 中间插入和删除是 O(n) |
| `deque` | 两端插入删除 | 比 `vector` 更适合队列类操作 |
| `list` | 频繁插入删除 | 不支持随机访问 |
| `stack` | 后进先出 | 常用于括号匹配、单调栈 |
| `queue` | 先进先出 | 常用于 BFS |
| `priority_queue` | 每次取最大或最小元素 | 本质是堆，操作是 O(log n) |
| `set` / `map` | 有序集合、键值映射 | 底层红黑树，查找插入删除 O(log n) |
| `unordered_set` / `unordered_map` | 快速查找和计数 | 平均 O(1)，但不保证有序 |

今天比较明确的一点是：刷题时不要只凭习惯用 `vector`。如果题目核心是查找、去重、计数、维护顺序、取最值，通常应该先想对应的 STL 容器。

## STL 算法

今天也复习了 `<algorithm>` 和 `<numeric>` 里常用的函数：

- `sort`：排序，最常用
- `stable_sort`：稳定排序
- `lower_bound` / `upper_bound`：二分查找边界
- `binary_search`：判断是否存在
- `reverse`：翻转区间
- `rotate`：旋转区间
- `max_element` / `min_element`：找最大最小元素
- `accumulate`：求和或累积计算
- `unique`：配合排序做去重

今天最大的提醒是：很多题不需要自己手写完整逻辑，先想标准库有没有现成算法。比如二分边界、求和、翻转、去重这些操作，用 STL 写出来更短，也更不容易出错。

## 今天做题的体会

今天复习完 STL 后做了一些题，主要是在练习容器和算法的选择。

做题时比较明显的问题是：有些题一开始会下意识写朴素循环，写到一半才发现可以用 `map`、`set` 或 `sort + two pointers` 简化。之后刷题要刻意训练这个流程：

1. 先看题目需要维护什么信息。
2. 判断是否需要顺序、去重、计数、快速查找、最大最小值。
3. 再选择 `vector`、`set`、`map`、`unordered_map`、`queue`、`priority_queue` 等容器。
4. 最后检查每一步复杂度是否能过。

## 今天的收获

今天把 STL 从“知道有这些东西”重新整理成了“刷题时怎么选”的思路。

现在对几个基础判断更清楚了：

- 要随机访问和顺序遍历，优先想 `vector`
- 要快速查找和计数，优先想 `unordered_map`
- 要自动有序，优先想 `set` / `map`
- 要先进先出，想 `queue`
- 要后进先出，想 `stack`
- 要动态维护最大值或最小值，想 `priority_queue`
- 要排序、二分、去重，先想 `<algorithm>`
