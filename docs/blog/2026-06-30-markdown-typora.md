# 2026-06-30：用 Typora 学 Markdown

今天用桌面上的 `Markdown教学文档_Typora.md` 系统过了一遍 Markdown。之前知道 `.md` 文件能写笔记和 README，但今天把常用语法、Typora 操作、图片路径、代码块、表格、公式这些点串起来了。

## 今天学到的核心

Markdown 本质上是一种轻量级标记语言，用很少的符号表达文档结构。它不追求像 Word 那样精细排版，更适合写学习笔记、技术文档、博客文章和项目说明。

今天最重要的收获不是背语法，而是理解了 Markdown 适合放进工程化写作流程里：

- 源文件是纯文本，直接打开也能读
- 适合放到 Git 仓库里管理修改记录
- Typora 适合入门和写作，VS Code 适合维护项目里的文档
- 图片、代码、表格、链接都能和普通文字放在同一份文档里

## 常用语法整理

### 标题

标题用 `#` 表示，`#` 越多，标题层级越低。

```markdown
# 一级标题
## 二级标题
### 三级标题
```

以后写博客时，一级标题只放文章标题，正文里的章节从二级标题开始。

### 段落和换行

Markdown 的段落之间要空一行。只按一次回车，很多时候还是同一个段落。如果需要强制换行，可以在行尾加两个空格，或者用编辑器提供的软换行。

### 加粗、斜体和删除线

```markdown
**加粗**
*斜体*
***加粗并斜体***
~~删除线~~
```

加粗适合标关键概念，但不能整段乱加，否则重点反而不明显。

### 列表

无序列表：

```markdown
- 标题
- 列表
- 表格
```

有序列表：

```markdown
1. 打开 Typora
2. 新建 Markdown 文件
3. 保存文档
```

任务列表：

```markdown
- [x] 学习标题
- [x] 学习列表
- [ ] 继续写博客
```

任务列表很适合记录每天的学习进度。

### 引用

```markdown
> 学习 Markdown 的关键，是多写、多看、多修改。
```

引用可以用来记录一句总结、摘录或提醒。

### 链接和图片

链接：

```markdown
[Typora 官网](https://typora.io/)
```

图片：

```markdown
![图片说明](图片路径或图片链接)
```

今天特别注意到：本地图片最好放到专门的素材目录里，并且和 Markdown 文件保持稳定的相对路径。否则文件移动之后，图片很容易失效。

推荐结构：

```text
文章.md
文章.assets/
  01.png
  02.png
```

### 表格

```markdown
| 工具 | 适合场景 | 特点 |
| --- | --- | --- |
| Typora | 学习和写笔记 | 所见即所得 |
| VS Code | 项目文档 | 适合代码仓库 |
| Obsidian | 知识库 | 适合长期积累 |
```

表格适合横向比较。以后比较工具、方案、学习路线时可以优先用表格。

### 代码

行内代码用反引号：

```markdown
使用 `print()` 输出内容。
```

代码块用三个反引号，并且最好标注语言：

````markdown
```python
def hello():
    print("Hello, Markdown!")
```
````

写技术博客时，代码块一定要标语言，这样预览时更清楚。

### 注释和 HTML 混写

Markdown 可以混写一部分 HTML。今天记住了几个常见写法：

```markdown
<!-- 这是一条注释，不会在正常预览中显示 -->

<u>下划线文字</u>

<kbd>Ctrl</kbd> + <kbd>S</kbd>
```

注释适合给自己留 TODO，但不能写密码、密钥、账号这类敏感信息。

### 公式

行内公式：

```markdown
勾股定理：$a^2 + b^2 = c^2$。
```

块级公式：

```markdown
$$
E = mc^2
$$
```

公式适合数学推导类笔记，但不同平台支持程度不一样，发布前要预览。

## Typora 和 VS Code 的分工

今天把工具选择也想清楚了：

| 工具 | 我以后怎么用 |
| --- | --- |
| Typora | 写学习笔记、整理语法、导出 PDF |
| VS Code | 写项目 README、博客文章、和代码一起维护的文档 |
| Obsidian | 以后如果要做长期知识库再考虑 |
| Word/WPS | 正式文档、论文、公文、需要复杂排版时使用 |

目前阶段，Typora 负责入门和写作体验，VS Code 负责项目文档和博客维护。

## 今天形成的写作习惯

以后写 Markdown 时先按这个顺序来：

1. 先写文章标题和二级标题，搭好结构。
2. 再补正文，不要一上来纠结排版。
3. 并列内容用列表，横向比较用表格。
4. 代码块标语言，图片放专门素材目录。
5. 写完后在目标平台预览一次，尤其检查图片、表格、公式和链接。

## 今日总结

Markdown 的语法本身不难，真正有用的是它能把学习笔记、项目说明和博客记录统一成一种轻量、清晰、容易维护的格式。
